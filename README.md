### 1. ☕ 3-Tier Java Application — DevOps CI/CD Pipeline
`Java` `Spring Boot` `Maven` `JUnit` `Jenkins` `SonarQube` `Docker` `Nexus` `Kubernetes/K3s` `Traefik` `AWS EC2` `AWS IAM` `AWS SSM`

A complete 3-tier Java application with an end-to-end automated CI/CD pipeline — from code commit to production deployment on Kubernetes.

**🔄 CI/CD Flow**
```
GitHub
   ↓
Jenkins (Build & Pipeline Orchestration)
   ↓
Maven Build & Unit Testing (JUnit)
   ↓
SonarQube (Code Quality Analysis)
   ↓
Docker Image Build
   ↓
Nexus Repository (Artifact/Image Push)
   ↓
Kubernetes / K3s Deployment (Traefik Ingress)
```

**What I Did**
- Developed and tested a Java-based 3-tier application with frontend and backend components using Spring Boot, Maven, and JUnit.
- Built an automated Jenkins CI/CD pipeline covering Maven build, unit testing, SonarQube static analysis, Docker image creation, and Nexus repository push.
- Containerized the backend with Docker and deployed it on a Kubernetes/K3s cluster, exposing services via Traefik ingress.
- Provisioned and managed the underlying AWS EC2 infrastructure, using IAM for access control and Systems Manager for secure remote administration.

**🔧 Troubleshooting Experience**
- Jenkins pipeline and plugin configuration issues
- Docker build and image push failures to Nexus
- Kubernetes/K3s and containerd image pull & networking issues
- SSH access and AWS infrastructure connectivity problems

### 3. 🔐 3-Tier Java CI/CD Pipeline — Jenkins, SonarQube & Nexus
`Java` `Jenkins` `SonarQube` `Nexus` `Docker` `AWS EC2` `EKS`

A hands-on 3-tier DevOps project where Jenkins, SonarQube, and Nexus are set up on separate EC2 instances to build a complete CI/CD pipeline for a Java-based Maven application, including code quality analysis, dependency checks, artifact management, and Kubernetes (EKS) deployment.

**🔄 CI/CD Flow**
```
GitHub → Jenkins → SonarQube → OWASP Dependency-Check
   → Maven Build & Test → Nexus Repository
   → Docker Image Build → Amazon EKS (Deployment)
```

**What I Implemented**
- Provisioned 3 separate EC2 instances (Jenkins, SonarQube, Nexus) on AWS.
- Installed Jenkins with required plugins (SonarQube Scanner, Nexus Artifact Uploader, Docker, Docker Pipeline, OWASP Dependency-Check, Eclipse Temurin, Pipeline Maven Integration).
- Configured global tools in Jenkins (JDK 17, Maven, Dependency-Check, Docker).
- Ran SonarQube and Nexus via Docker containers.
- Integrated Jenkins with SonarQube and Nexus using authentication tokens and Maven `settings.xml`.
- Set up an EKS cluster for application deployment.

**🔧 Troubleshooting Experience**
- Jenkins plugin and tool version compatibility
- Docker container access and permission issues
- SonarQube-Jenkins token authentication
- Nexus repository credential and URL mismatches
- Security group/port configuration across 3 instances (8080, 9000, 8081)
